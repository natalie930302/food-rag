# food-violation-severity-model

> 本專案已併入 [food-rag](https://github.com/natalie930302/food-rag) 的 `experiments/severity-regression/`,與其資料來源放在同一個 repo 內維護;此處保留原始歷史供連結使用。

用食品/健康食品違規廣告的真實裁罰案例(台北市政府公告114-115年,400筆)訓練模型,**預測罰款金額**(log尺度迴歸)。資料來自 `food-rag` 專案已蒐集的裁罰公告。

## 為什麼是迴歸,不是分類?

原本規劃做「違規/合規」二元分類,但實際資料全部400筆都是**已確認違規**的案例(裁罰公告本身就只公告違規案件),沒有「合規」的負樣本可用,勉強生成假的合規範例會失真。改用資料裡本來就有的 `penalty_twd`(罰款金額)當預測目標,是一個誠實、不需要造假資料的迴歸任務:從違規廣告的文字內容,預測這個違規案件的嚴重程度(用罰款金額當代理指標)。

## 資料

- 來源:台北市政府 114–115 年違規食品廣告裁罰公告,400 筆,含違規文字、罰款金額、法條依據。由 [food-rag](https://github.com/natalie930302/food-rag) 的 `make ingest` 從原始公告解析產生(`data/processed/violations.jsonl`)
- **資料與模型產物不隨本 repo 提供**(`.gitignore` 排除 `data/*.jsonl`、`*.csv`、`*.joblib`、`*.pt`)。重現時先跑 food-rag 的 ingest,再把 `violations.jsonl` 複製到本專案 `data/`,或 `python prepare_data.py <path>` 直接指定路徑
- 切分:train 280 / val 60 / test 60(依隨機切分,無時間洩漏疑慮因為都是獨立裁罰案件)
- 目標值取 log(罰款金額),因為金額分佈右偏(40,000 ~ 1,980,000元)

## 實驗結果

| 方法 | val R² | test R² | test 約當金額誤差(MAE) |
|---|---|---|---|
| **Baseline**: 字元TF-IDF(2-4gram) + Ridge迴歸 | 0.548 | 0.391 | NT$29,642 |
| **微調 bert-base-chinese**(4 epochs, CPU) | 0.057 | -0.278 | NT$47,870 |

## 重要發現:微調 BERT 反而輸給簡單 baseline

這是這個專案最有價值的部分。直覺上「用更大的預訓練模型微調」應該表現更好,但實驗結果相反:

- BERT 微調在 epoch 1 之後就沒有穩定進步(val R² 在 -0.2 ~ 0.06 之間震盪,見 `src/train_bert.py` 訓練log)
- 推測原因:**280筆訓練資料對一個1億+參數的模型來說太小**,容易overfit或訓練不穩定;而TF-IDF+Ridge只有5000維特徵+簡單線性模型,參數量遠小於資料量,泛化能力反而更好
- 這印證了機器學習裡常見的原則:**模型複雜度要跟資料量匹配**,不是模型越大越好

## 延伸驗證:換更小的模型、加強正則化,問題依然沒解決(2026/09新增)

原本的負向結果可能有兩個可以檢討的地方:bert-base-chinese 參數量太大(~102M),而且訓練時沒有額外正則化。這輪驗證換成參數量只有原本1/3的蒸餾版中文模型(`hfl/rbt3`,~38M參數),同時把 dropout 從0.1提高到0.3、AdamW加上weight_decay=0.01,並且用驗證集R²挑best checkpoint(而不是直接用最後一個epoch),排除訓練後期overfit epoch拖累結果的可能性。

| 方法 | 參數量 | val R² | test R² | test約當金額誤差(MAE) |
|---|---|---|---|---|
| **Baseline**:TF-IDF+Ridge | — | 0.548 | **0.391** | NT$29,642 |
| bert-base-chinese 微調 | ~102M | 0.057 | -0.278 | NT$47,870 |
| **hfl/rbt3 微調(更小+強正則化+best checkpoint)** | ~38M | -0.024 | **-0.514** | NT$52,227 |

**結果比原本更差,不是更好**:即使模型參數量降到1/3、加了正則化、還挑了validation表現最好的checkpoint,test R²不但沒有回升,反而從-0.278掉到-0.514。更值得注意的是,連**訓練集**本身的R²都是負的(-0.039)——代表這個模型連自己的訓練資料都沒有學到穩定的擬合,不是「overfit到訓練集、對測試集失效」的典型overfitting模式,是整個訓練過程本身在這個資料量級下就沒有學到可靠的訊號。

**這個結果讓原本的結論更站得住腳,而不是被推翻**:一開始的假設是「bert-base-chinese太大」,如果換小一點的模型/加正則化就能救回來,這輪驗證直接否定了這個假設——問題不是單純的模型大小或正則化強度,更可能是「用預訓練transformer的[CLS]表徵去微調做迴歸」這個做法本身,在280筆這個資料量級下就是不穩定的,不管換多小的transformer都一樣。TF-IDF+Ridge的優勢不是因為BERT系列模型剛好選錯了大小,而是因為它的歸納偏誤(bag-of-ngrams特徵+線性模型+L2正則化)本身就跟這個資料量級更匹配,這是架構層次的差異,不是超參數層次能補救的。

## 與理論的關聯

這個結果對應統計學習理論裡的 **Bias-Variance Tradeoff(偏差-變異權衡)**:bert-base-chinese 參數量破億,屬於低偏差、高變異的模型類別,在只有280筆訓練樣本時,高變異主導了誤差,導致驗證集表現不穩定甚至劣化;TF-IDF+Ridge 的模型複雜度(特徵數雖多但是線性模型,且有L2正則化)跟這個資料量級更匹配,變異被控制住,反而泛化較好。這也連結到近年關於「小資料場景下微調策略是否划算」的研究方向,例如 LIMA、AlpaGasus 等工作顯示精心篩選/控制訓練規模的資料反而可能優於直接大量微調——本專案的負向結果是這類問題的一個反例:**沒有針對小樣本做額外正則化/資料篩選設計的直接微調,在資料量不足時風險很高**,而不是「微調永遠比傳統方法好」。

## 研究歷程

### 研究動機與路徑

原本規劃的是「違規/合規」二元分類,但實際打開 `food-rag` 蒐集到的資料才發現一個根本問題:裁罰公告本身就只公告違規案件,400筆全部都是已確認違規,沒有一筆「合規」的負樣本。這裡有個岔路:硬湊一批假的合規範例讓原本規劃的分類任務跑得起來,或是老實承認資料不支援這個任務、重新設計一個資料本身就能誠實回答的問題。選了後者——用資料裡本來就有的罰款金額當預測目標,改成迴歸任務。這個決定本身就是研究方法上的一個判斷:**不因為原始規劃更「完整」就勉強套用會失真的資料**。

任務確定後,研究路徑刻意設計成一次直接的對照:同一份280筆訓練資料,分別用一個極簡模型(TF-IDF+Ridge)跟一個參數量破億的預訓練模型(bert-base-chinese微調)做,目的就是驗證「用更大的模型微調」這個直覺是否站得住腳。結果是負向的——BERT微調全面輸給簡單baseline。這個結果沒有被當成單一案例的意外,而是回頭去對照 `civil-law-qa-bot` 的TSDAE微調負向結果,發現兩者是同一個原則(模型複雜度要跟資料量匹配)在不同任務、不同模型架構上的第二次獨立驗證——這讓這個原則從「單一案例的觀察」變成一個有跨專案證據支持的模式。

### 研究方法

- **目標值做log轉換**:罰款金額分佈右偏(40,000~1,980,000元),迴歸前先做log轉換是處理右偏標籤的標準做法,不是隨意的前處理
- **刻意選兩個複雜度差距懸殊的模型做對照**:不是漸進式調參數,是直接對照「極簡vs.極複雜」兩端,讓「模型複雜度跟資料量要匹配」這個假設的驗證更明確
- **不只看最終R²,追蹤訓練過程的穩定性**:BERT微調的判斷依據不只是最終test R²,還包含每個epoch的val R²有沒有穩定進步(見`train_bert.py`訓練log)——確認負向結果是訓練本身不穩定,不是單純運氣不好卡到一個差的random seed

### 遇到的困難

- **原始分類任務規劃在拿到真實資料後才發現不可行**:這不是寫程式時遇到的bug,是資料蒐集完成後才發現的任務設計問題,處理方式是重新設計任務而不是硬套資料
- **BERT訓練不穩定,不是單純"分數不好"**:val R²在epoch之間震盪(-0.2~0.06),需要判斷這是訓練本身有問題還是就是這個資料量級下的真實表現——最後判斷是後者,280筆資料撐不起一個上億參數模型的穩定訓練

### 時程(依實際執行順序)

1. 規劃二元分類任務 → 發現資料只有違規樣本,無法支援 → 重新設計成迴歸任務
2. 建立 TF-IDF + Ridge baseline
3. 訓練 bert-base-chinese 微調 → 得到負向結果
4. 對照 civil-law-qa-bot 的 TSDAE 負向結果,確認是同一原則的第二次獨立驗證
5. 延伸驗證「換更小模型+加強正則化」能否解決問題 → 結果更差(test R² -0.514),排除「單純模型太大」這個假設,確認問題出在transformer微調本身跟這個資料量級不匹配,不是超參數層次能救的

## 學習筆記

- **這個專案讓我學會怎麼正確地「排除一個假設」,而不是隨便換個做法就宣稱有改善或沒改善**。換更小模型那次,如果只換模型大小,結果不好我還是沒辦法確定是不是模型太大——是同時控制dropout、weight decay、checkpoint選擇,確定「不是超參數沒調好」,才能真正排除「單純模型太大」這個假設。少了任何一個控制變數,這個結論都不能下得這麼肯定。
- **檢查訓練集本身的表現,幫我抓到了一個原本會被誤判的結論**。如果只看test R²變差,我可能會寫成「過擬合更嚴重」;但訓練集R²也是負的,說明根本不是過擬合,是這個做法本身學不到穩定訊號——這個區別對整個研究結論的方向影響很大,值得養成習慣去檢查。
- **一開始規劃的二元分類任務做不下去,不是失敗,是及早發現資料不支援這個問題**。這件事讓我體會到,研究設計要看資料而不是看原本的規劃——固執地想辦法讓資料配合原始計畫(例如硬湊假的合規樣本),得到的會是一個看似完整但其實站不住腳的結果。
